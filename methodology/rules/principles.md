# Cross-Cutting Principles

- Working software is the true test. Analysis and docs support it, but do not replace it.
- Sequential stages, not walls. Feedback from later stages refines earlier ones.
- Good enough, not perfect. Reach adequacy, not false certainty.
- Rigor scales with risk. Project type, change scale, and predictability shape process.
- Traceability is non-negotiable. Work that does not trace to a goal should be questioned.
- Documentation is a first-class deliverable, not an afterthought.
- Design the procedures first. For anything a human operates over time, the operating procedure is a design input, not an operations output. Walk the steps — rarest first — against the state each previous step actually leaves.
- Filing is part of deferring. Anything deferred, queued, routed, or accepted as debt is written into the tracking artifact as you defer it, and the sentence that defers cites the entry by identifier. Prose that defers without a citation is tracking nothing — saying "queued for triage" does not queue it.
- State belongs to its owner. Outside the artifact that owns a work item's state, a claim about that state is dated or absent — never an undated present tense. Where a claim cannot abstain, the moment that changes it is a named step in the method, not a sweep.
